-->Maps and Unordered Maps — Complete Theory
1. Map: A map is an associative container that stores data in key-value pairs.
        Each key is unique and is used to identify its corresponding value.
        A map keeps all keys in sorted order by default.
        Internally, map is generally implemented using a Red-Black Tree, which is a self-balancing Binary Search Tree (BST).
        In a BST, smaller keys are placed on the left and larger keys on the right.
        A normal BST can become skewed and have O(n) height. A Red-Black Tree prevents this by maintaining balance using red/black coloring, recoloring, and tree rotations.
        Important Red-Black Tree properties include:
                Every node is either red or black.
                The root is black.
                NULL/NIL leaves are considered black.
                A red node cannot have a red child.
                Every path from a node to its descendant NIL leaves contains the same number of black nodes.
                These rules keep the height of the tree O(log n).
        Since searching, inserting and deleting require traversing the tree, these operations take O(log n) time.
        map maintains ordering, so elements can be traversed from the smallest key to the largest key.
        It also supports ordered operations such as lower_bound() and upper_bound().
        map is preferred when ordering is important or when guaranteed O(log n) performance is required.

        Time Complexity:
                Operation	Complexity
                Search / Fetch	O(log n)
                Insertion	O(log n)
                Deletion	O(log n)
                Traversal	O(n)

        Key idea:
        Map → Red-Black Tree → Balanced Tree → Sorted → O(log n)

2. Unordered Map: An unordered map is an associative container that stores data in key-value pairs.
        Each key is unique, but unlike map, the keys are not stored in sorted order.
        It is generally implemented using a Hash Table.
        A hash table consists of multiple buckets where key-value pairs are stored.
        A hash function converts a key into a bucket/index where the corresponding element should be stored.
        Because the bucket can usually be determined directly from the key, searching, inserting and deleting are O(1) on average.
        However, different keys can produce the same bucket. This is called a collision.
        When collisions occur, multiple elements are stored in the same bucket and the required key may need to be searched among them.
        If collisions are limited, lookup remains close to O(1).
        In the worst case, many or all keys can end up in the same bucket. The container may then need to examine the elements one by one. Therefore, worst-case complexity can become O(n).
        An unordered map also uses a load factor, which represents how full the hash table is. A high load factor can lead to more collisions.
        When necessary, the hash table performs rehashing, where the number of buckets is increased and existing elements are redistributed according to their hash values.
        Rehashing can make an individual operation expensive, but insertion is O(1) on average/amortized.
        unordered_map is preferred when fast key-based lookup is more important than ordering.

        Time Complexity:
                Operation	Average	Worst Case
                Search / Fetch	O(1)	O(n)
                Insertion	O(1)	O(n)
                Deletion	O(1)	O(n)

        Why worst-case O(n)?
        If many keys collide into the same bucket, the hash table may have to check n elements one by one, making the operation O(n).

        Key idea:
        Unordered Map → Hash Table → No Ordering → O(1) Average → O(n) Worst Case
